Optional settings plugin for `@tak1208/dsh-webui-transition`. It adds a **Transitions** page to the DSH (DeepSeek Harness) Web GUI Settings dialog for choosing how the main plugin falls back when it cannot infer the trigger element.

## Entry

**Settings → Transitions** (Chinese UI: `过渡动画`). The nav row shows the outline icon (`settings.section.icon`, generated from `assets/icons/outline.svg` by `pnpm build`; the slot is provided by dsh 0.2.2-alpha.3 and newer, older versions fall back to the shell's default gear).

## Options

| Setting | Values | Default | Meaning |
| --- | --- | --- | --- |
| Fallback without an anchor | `Fade only` / `Pointer origin` | `Fade only` | How an overlay enters when the trigger element cannot be inferred |

- **Fade only** (`fade`): no geometric animation for this surface, opacity only.
- **Pointer origin** (`pointer`): scale from the most recent pointer position and translate towards it; when no pointer position is available it still degrades to fade only.

## Storage

- `localStorage` key: `dsh.webui-transition.settings.v1`
- Value: JSON `{ "fallback": "fade" | "pointer" }`, default `{ "fallback": "fade" }`
- Takes effect immediately within the same tab (Cordis event); other tabs are synced through the `storage` event.
- Clearing site data, private windows, a changed origin (port/host), or a different browser/profile wipes the value; the only consequence is falling back to the default `fade`, and the main plugin keeps working.

## Relationship to the main package

One npm package can only provide one client plugin, so this settings plugin is a separate package. The root package `@tak1208/dsh-webui-transition` depends on it via `workspace:^`, so installing the root package installs it as well; publish this package before the root package.

**The main plugin does not depend on this plugin**: without the settings plugin, or when no setting has ever been saved, the main plugin always runs normally with the default `fade`. This plugin only provides the settings UI and the settings panel's center-origin marker (`data-dsh-transition-origin="center"`: the main plugin recognises only that marker, not host attributes); it does not implement the animation itself. Without this plugin the settings panel falls back to the main plugin's default origin-aware behaviour.

## Implementation

- `src/browser.js`: client entry, `inject = ["slots", "locale"]`; registers the `settings.section` page, the `settings.section.icon` nav icon, and the zh/en dictionaries.
- `src/nav-icon.js`: the `settings.section.icon` component, **generated from `assets/icons/outline.svg` by `pnpm build` — do not edit it by hand**; the generator supports a whitelist of elements/attributes (anything else fails the build), sizes come from the shell, and colors inherit `currentColor`.
- `src/settings-page.js`: `createSettingsPage`, rendered with `SegmentedControl` from the shell baseline module `@deepseek-ai/dsh-client-ui-primitives` (no hand-written segmented control; layout uses `--dsw-*` tokens only).
- `src/panel-marker.js`: observes `document.body` and marks an inserted settings panel (`[role="dialog"][data-shortcut-modal="settings"]`) with the center-origin marker `data-dsh-transition-origin="center"`; the marker value is the shared opt-in contract with the main plugin.
- `src/contract.js`: the same settings contract as the root package `src/settings.js`, implemented independently (kept in sync by root-repo tests), plus the cross-package center-origin marker constants.
- `client.js`: build artifact (generated by `pnpm build` in the root repo; do not edit by hand).
